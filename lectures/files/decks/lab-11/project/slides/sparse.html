A sparse file has holes

student@server: ~/oslab-work/lab11

$ truncate -s 8M images/demo-sparse.img

$ dd if=/dev/zero of=images/demo-written.img bs=1M count=8 status=none

$ ls -lh images/demo-*.img

$ du -h images/demo-*.img

truncate -s 8M sets the length to 8 MiB without writing the bytes. The unwritten part is a hole: reads give zeros, and no block is used.

dd copies bytes. Here it writes 8 MiB of real zeros, so every block is allocated.

Both files have the same length. du shows the difference.
