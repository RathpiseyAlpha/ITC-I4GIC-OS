Multilevel Feedback Queue (MLFQ)

Week 6 — watch processes move down when they use a whole quantum, stay up when they give the CPU back early, and get rescued by a priority boost
🎯 Learning objectives — what you should be able to do (click to minimize)
  • State the rules that move a process between the queues of an MLFQ.
  • Explain how MLFQ separates CPU-bound from interactive (I/O-bound) processes without being told which is which.
  • Show how a long process can starve, and how a periodic priority boost (aging) fixes it.
  • Explain how a process can game the scheduler by giving up the CPU just before its quantum ends.

“I/O every” = the process asks for I/O after that many time units of CPU (0 = never, a pure CPU-bound job). Each I/O takes 2 time units, then the process returns to the same queue it left.

Scenario and rules

time units
Rules. 1) A new process enters Q0. 2) If it uses its whole quantum, it moves down one queue. 3) If it blocks for I/O first, it keeps its queue. 4) A process in a higher queue preempts one from a lower queue. 5) Q2 is FCFS. 6) With boost on, every process returns to Q0 at each boost.
